03 · LOOP

loop 上的四个可控点

transformContext → convertToLlm

每次调用前先裁剪、注入上下文，再过滤掉 UI 专用消息，把自定义消息转成 LLM 能懂的三种角色。

toolExecution: parallel

默认并发执行工具，结束事件按完成顺序发，toolResult 消息仍按助手原顺序落盘。

beforeToolCall / afterToolCall

前者可拦截执行，后者可改写结果；整批都返回 terminate: true 时，跳过后续 LLM 调用。

steer() / followUp()

steer 等本批工具执行完才注入，下个 turn 生效；followUp 只在 agent 本要停下时才检查。

来源：packages/agent/README.md；src/agent-loop.ts（agentLoop）、src/agent.ts（Agent 类）

Loop 的深入点，挑一个讲透：推荐 parallel。工具调用先按顺序做预检，通过的并发执行；tool_execution_end 按完成顺序发出，但落盘的 toolResult 仍按助手消息里的原顺序，turn_end 里的 toolResults 也一样。并发换速度，顺序保证 transcript 稳定。任一工具声明 executionMode: "sequential"，整批就改为顺序执行。
