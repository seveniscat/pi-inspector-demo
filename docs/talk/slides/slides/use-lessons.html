02 · USE

用 Pi 写代码的常用用法

AGENTS.md

项目规则写一次

构建命令、代码规范、不能碰的目录写在仓库根目录。Pi 从工作目录及上级目录加载，启动头可以确认。

.pi/prompts/review.md

重复的提示做成命令

文件名就是命令名：/review。支持 $1、${1:-默认值} 等参数，团队可以共享。

!npm test · !!git status

命令输出直接交给模型

! 把命令和输出放进对话，模型据此修改；!! 只在终端执行，不发给模型。

/tree · /fork

换思路不丢现场

/tree 在同一会话里回到早先节点另开分支；/fork 拆成独立的新会话。

pi --tools read,grep,find,ls

只读审查

不开放 edit、write、bash，模型只能读代码；已配置的 MCP 工具默认仍保留。

git diff | pi -p "Review"

一次性调用

-p 输出最终回答后退出，适合脚本和管道；--mode json 改为输出事件流。

来源：coding-agent docs：usage.md、cli.md、prompt-templates.md、sessions.md、configuration.md

这一页是用 Pi 写代码的六个常用用法，都来自官方文档（usage.md、cli.md、prompt-templates.md、sessions.md、configuration.md）。讲的时候每条配一句你自己用过的场景，比只念用法更有说服力。几个细节：AGENTS.md 也可以写成 CLAUDE.md，同一目录下的 AGENTS.override.md 会替换它；项目级模板放在 .pi/prompts/，个人模板放在 ~/.pi/agent/prompts/，新增或修改后执行 /reload；项目配置要在项目被信任后才加载。--tools 用普通名字时是白名单，会替换整个默认工具集；MCP 工具除非白名单里写了 mcp__ 开头的条目，否则保留。-p 在 stdin 或 stdout 被重定向时是默认行为。
