进程挂了能接上吗？三种做法

内置：会话级恢复

会话自动落盘为 JSONL，pi --continue 接上对话。

中断的工具调用不会续跑；发给模型前，pi-ai 为它补一条 “No result provided” 错误结果。

扩展：事后补救

demo 里的 resume 扩展：checkpoint 写进 JSONL，重启时找出悬空的调用。

用 context 钩子补一条“已中断”结果，不改 Pi 源码。

Pi Durable：存储层

输出、工具调用、队列先提交到存储，再展示；崩溃后从最后一个 checkpoint 继续。

只有声明 replay: "safe" 的工具会重跑，其余拿到 interrupted 结果。

现状：Pi Durable 随 1.0 发布，官方标注实验性，API 会变。存储支持 Memory、SQLite、JSONL、Cloudflare Durable Object。会重跑的工具若有副作用，要自己保证幂等。

来源：earendil.com/posts/pi-durable；packages/durable/README.md；pi-ai src/api/transform-messages.ts

三栏从左到右是递进关系：内置只把历史读回来，中断的调用由 pi-ai 在发请求前补一条 "No result provided" 的错误结果，保证请求合法，但任务不会自动续跑；扩展能明确告诉模型"被中断了"并接着做，但只是事后补救；Durable 从存储层解决，每一步先提交再展示。官方的 Durable 实验版 coding agent 在 v1.1.0 的 packages/coding-agent/src/experimental/durable，用 SQLite 存会话，kill 后用 --continue 重开，中断的调用拿到 interrupted 结果，turn 正常结束。1.2.0 移除了整个实验性 server/client 栈，这个 agent 也在其中，所以 demo 第 6 步在 v1.1.0 tag 上运行。
