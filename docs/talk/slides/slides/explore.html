我们可以从哪里开始探索

方向 A

嵌进研发流程

print / JSON 与 RPC 模式让 Pi 可被脚本、CI 和其他程序驱动；官方另有 pi-chat 仓库做聊天自动化。

方向 B

接入内部工具与数据

用自定义 tool 或 MCP server 把内部系统交给 agent，入口是 registerTool 与 registerMcpServer。

方向 C

长期运行的助手

任务可中断、可恢复。Pi Durable 已有实验性实现，适合跟踪和小范围试验。

采用前提：生态活跃，仓库约 11.5 万 star；迭代也很快，9 月 29 日到 10 月 12 日发了 10 个版本（0.99.0 → 1.2.0），破坏性变更不少，升级前先读 changelog。

来源：earendil-works/pi README 与 Releases；docs/extensions.md；packages/durable/README.md

A 和 B 现在就能动手试；C 适合先跟踪。这里只列方向，不预设团队的具体场景。破坏性变更的例子：1.0.3 把 azure-openai-responses provider 改名为 azure；1.2.0 改变了 before_agent_start 的事件结构，并移除了实验性的 server/client 栈。
