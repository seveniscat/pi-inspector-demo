03 · EXTENSIONS

边界：Pi 不替你画，要自己画

Pi 不内置权限系统，以启动它的用户权限运行；文件、进程、网络、凭据都不设限。

扩展在 Pi 进程里运行，能读到提示词、工具调用、文件、凭据和会话历史。

tool_call 钩子能做确认和拦截，但它是进程内的约束；要隔离，靠容器或沙箱。

Gondolin 扩展

Pi 与凭据留在宿主，内置工具和 ! 命令走本地 Linux micro-VM

Plain Docker

整个 Pi 进程放进本地容器，最简单

Docker Sandboxes

托管沙箱，provider 凭据留在宿主、由代理替换

OpenShell

整个 Pi 进程放进带策略的沙箱，本地或远程

来源：README「Permissions & Containerization」；docs/extensions.md；docs/containerization.md

这一页把开头「刻意留白」里的权限问题落地。真正要决定的是：我们愿意把 Pi 放在哪种隔离级别里运行。注意 Gondolin 只把内置工具和 ! 命令放进 VM，其他扩展的工具仍在宿主上运行，命令也会继承宿主的环境变量；其余三种把整个进程放进隔离环境，扩展也一起被隔离。凭据处理不同：Plain Docker 要把凭据传进容器，Docker Sandboxes 把 provider 凭据留在宿主由代理替换，OpenShell 用策略控制。
