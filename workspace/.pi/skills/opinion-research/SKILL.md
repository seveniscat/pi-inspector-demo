# 舆情分析链路

## 先理解数据长什么样

- 数据是**按监测词抓取**的：每条帖子都有"来自搜索"（监测词）。监测词决定了研究对象和话题划分，不需要用户告诉你研究什么。
- **帖子只有标题，没有正文**；观点几乎全在评论里。评论量远大于帖子量，结论主要靠评论支撑。
- 帖子和评论都**自带情绪标签**；帖子有**相关性标签**（如「相关」），不相关的是抓取噪音。
- 部分时间只有日期，时间线精确到天即可。

## 可续做（幂等）——任何一步开始前先检查

- `research/plan.md` 存在 → 已盘点过、已拆好话题，直接按它继续，不要重做第 0～3 步。
- `research/topics/` 下已有某个话题的笔记 → 这个话题已完成，跳过；`research/risk.md` 同理。
- 每写完一份文件（plan.md、每份话题笔记、risk.md、报告）**立刻**调用 `checkpoint`：`task` 填监测对象，`done` 传已完成项的完整列表（如 `["话题1","话题2"]`），`total` 填 plan.md 里定的总数。
- 工具结果出现 `[interrupted]`：那一步执行到一半进程被杀了，先 `ls` / `read` 核实文件状态再决定是否重做。
- 查询工具带缓存，重复同样的查询是安全的。

## 第 0 步：解析需求（不调工具）

用户可能只说一句"分析一下最近 7 天的舆情"。提取：对象（没说就从数据推断）、时间（默认数据中最近 7 天）、关注点（默认综合研判；问"有没有风险"就把风险扫描放在最前、写得最细）。

## 第 1 步：数据盘点

`dataset_info`，然后回答并记下：
- **监测对象**是谁？从监测词里找共同主体（品牌 / 产品 / IP）
- 有哪些**监测话题**（各监测词及帖子数）
- 平台、时间范围、样本量；相关性取值分布 → 默认只用「相关」的帖子，记下排除了多少

## 第 2 步：全局概览（只看相关帖子，传 `relevance`）

- `social_trend` 按天：新评论走势、消极占比，找出拐点日
- `social_trend` 按平台：讨论集中在哪
- `social_trend` 按监测词：哪个话题声量最大、哪个最负面

## 第 3 步：拆题并写计划

**话题单元 = 监测词**。按评论量排序取前 4 个监测词作为话题；剩下的如果还有一定评论量，合成一个"其他"话题（总共最多 5 个）。用户只关心某个方面时，只保留相关的监测词。

写 `research/plan.md`：
1. 研究范围：监测对象、时间、平台、样本量、排除的不相关帖子数
2. 全局概览的关键数字和拐点
3. 话题清单：每个话题的监测词、帖子数、评论数、消极占比、准备重点看什么
4. 进度总数 = 话题数 + 2（风险扫描、报告）

写完调用 `checkpoint`，`done` 传 `[]`。

## 第 4 步：逐话题深挖（一次只做一个）

对每个话题（监测词 X），都带上 `query: X, relevance: "相关"`：
1. `social_search` 按评论数排序看最热的 5 条，再按消极评论数排序看最负面的 5 条
2. `get_post` 读 1～2 个讨论最多的帖子的高赞评论（每个话题**最多 3 次**）
3. `search_comments` 分别看高赞的消极评论和积极评论，归纳出 2～4 个主要观点
4. 某个观点想知道有多普遍，用 `search_comments` 加关键词看命中数（报告里说明这是"关键词命中数"）
5. 写 `research/topics/<序号>-<监测词>.md`（格式见下），调用 `checkpoint`

## 第 5 步：风险扫描（跨话题）

1. `search_comments` 不限话题，看点赞最高的 30 条消极评论
2. `social_search` 按消极评论数排序，看最负面的帖子
3. 结合第 2 步的拐点：每个风险点看它集中在哪些帖子 / 平台、从哪天开始、有没有跨帖子跨平台扩散、有没有官方回应
4. 写 `research/risk.md`：风险清单（风险 / 等级 高中低 / 依据 / 涉及 ID），调用 `checkpoint`

## 第 6 步：写报告

读 plan.md、全部话题笔记和 risk.md，写 `report/report.md`（格式见下），调用 `checkpoint`，`note` 写"报告已生成"。

## 第 7 步：自检

逐条检查：报告里每个帖子 / 评论 ID 都能在笔记里找到；每个数字都来自工具结果；没有评论用户昵称。有问题就改，最后用一句话说明自检结果。

## 判断规则

- **代表性**：一条高赞评论比十条零赞评论更有代表性；说明结论依据的是条数还是点赞量。
- **情绪标签可能误判**：关键结论用评论原文佐证，不要只报比例。
- **事实和传言分开**：只有个别评论提到、没有其他佐证的，标"待核实"。
- **证据可追溯**：每个观点至少引用 2 个评论 ID 或帖子 ID；不允许编造 ID 或引文。
- **脱敏**：不写评论用户昵称；帖子作者是官方、媒体、大号的可以写。

## 话题笔记格式

```markdown
# 话题 N：<监测词>
## 声量与情绪
帖子 X 条，评论 Y 条，消极占比 Z%（来自 social_trend）
## 主要观点
- 【负面】观点概括（关键词命中约 N 条；证据：[评论ID]、[评论ID]）
- 【正面】……
## 代表帖子
- [帖子ID] 平台 日期 评论数：标题
## 待核实
- 没有就写"无"
```

## 报告格式

```markdown
# <监测对象> 舆情分析报告（<起止日期>）
> 数据：平台、帖子 N 条（相关 M 条）、评论 K 条；情绪标签来自数据源

## 一句话结论
## 1. 总体态势（按天走势表、平台分布、话题声量与情绪对比）
## 2. 分话题分析（每个监测话题一小节：声量情绪 / 主要观点 / 代表帖子）
## 3. 风险提示（表格：风险 | 等级 | 依据 | 建议动作）
## 4. 建议（3 条，具体到动作）
## 附：证据索引
```
