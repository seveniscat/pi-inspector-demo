# 舆情研究流程

目标：对用户给定的研究对象和时间范围，回答 4 个研究问题，每个问题沉淀一份证据笔记，最后汇总成 `report/report.md`。

## 关键原则：可续做（幂等）

这个任务随时可能被中断，每一步都要能安全地重来：

- 开始前先看 `research/plan.md` 是否存在。**存在就按它继续**，不要重新拆问题。
- 处理某个问题前，先看 `research/` 下是否已有对应的 `qN-*.md`。**已存在就跳过。**
- 每写完一份证据笔记，**立刻**调用 `checkpoint`：`task` 填研究对象，`done` 传已完成问题编号的完整列表（如 `["Q1","Q2"]`），`total` 填 4。
- 上下文里出现 `[interrupted]` 标记的工具结果，说明那一步执行到一半进程被杀了：先用 `ls` / `read` 核实文件状态，再决定是否重做。
- 重复查询是安全的：查询工具带缓存，同样的条件不会重复访问数据服务。

## 步骤

1. **摸底**：用 `social_trend` 看研究对象在时间范围内按天的声量和情绪走势，找出突增的日子。
2. **拆计划**：写 `research/plan.md`，固定 4 个问题，每个问题下写 1～2 句打算怎么查（用哪些关键词 / 话题 / 平台）：
   - Q1 声量与情绪：整体走势、各平台分布、拐点出现在哪天、为什么
   - Q2 产品口碑：主要好评点和差评点，各给代表性帖子
   - Q3 风险事件：有没有负面事件；如果有，梳理时间线（首发 → 发酵 → 回应 → 回落）、波及范围、品牌回应效果，区分事实和谣言
   - Q4 竞品对比：和主要竞品相比，讨论里的优劣势各是什么
   写完调用 `checkpoint`，`done` 传 `[]`。
3. **逐个问题研究**，一次只做一个：
   1. 用 `social_search` 按计划查询，必要时调整关键词、按时间排序、翻页
   2. 挑最有代表性的帖子用 `get_post` 读全文和热评（每个问题 **不超过 4 次**，控制上下文）
   3. 写 `research/qN-<简短主题>.md`，格式见下方"证据笔记格式"
   4. 调用 `checkpoint`
4. **写报告**：读取全部证据笔记，写 `report/report.md`，格式见下方"报告格式"。最后调用一次 `checkpoint`，`note` 写"报告已生成"。

## 数据判断规则

- **噪音单独处理**：作者类型为"营销号"的帖子、正文含"转发抽奖 / #抽奖"、"#合作 / #广告"的帖子，不计入口碑和情绪判断；可以在 Q1 里说明它们的数量和影响。
- **区分事实和传言**：只有一两个账号的说法、没有官方或媒体佐证的，标为"待核实"；与官方说明或媒体报道矛盾的，标为"不实"并给出依据。
- **看传播不只看数量**：一条高互动的帖子可能比十条零互动的帖子更重要，结论里说明你依据的是数量还是互动量。
- **证据必须可追溯**：每条结论至少引用 2 个帖子 ID；不允许编造帖子 ID 或引文。

## 证据笔记格式

```markdown
# QN <问题>
## 结论
- 结论 1（证据：[帖子ID]、[帖子ID]）
- 结论 2（证据：…）
## 关键证据
- [帖子ID] 平台 日期 作者类型 互动量：一句话摘录
## 待核实 / 存疑
- 没有就写"无"
```

## 报告格式

```markdown
# <研究对象> 舆情研究报告（<起止日期>）
> 数据来源：<数据服务或"演示语料">；样本量与噪音剔除说明

## 一句话结论
## 1. 声量与情绪
## 2. 产品口碑
## 3. 风险事件（时间线表格：时间 | 事件 | 证据）
## 4. 竞品对比
## 5. 建议（3 条，具体到动作）
## 附：证据索引（帖子 ID 列表）
```
